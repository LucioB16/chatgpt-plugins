Privacy policy

Effective date: October 24, 2026 · Publisher: Lucio Bottacin

Your conversations and files are not sent to a server operated by the developer of Lyra or Iterloom.

This policy describes the data practices of Lyra and Iterloom, two independent skills-only AI plugins created by Lucio Bottacin, and of this supporting website. It distinguishes what the plugins process inside the AI host from what the developer receives.

1. Information processed to provide the plugins

  • Lyra: processes the requests, constraints, and examples you provide to produce improved prompts.
  • Iterloom: processes the conversation context made available by the host for your request and, optionally, chat exports or other files you intentionally provide for analysis. The amount of historical context available may be limited.
  • Contextual information: the AI host may supply relevant conversation or tool context according to its own settings and permissions.

These inputs are handled by the host AI product and its execution environment. The plugins contain packaged instructions and supporting resources; neither currently includes a developer-operated MCP service, independent user database, login, or analytics integration.

2. Information collected by the developer

Ordinary plugin use: the developer does not automatically receive, collect, or store your prompts, chat transcripts, attached files, conversation exports, or plugin usage telemetry. No copies of these inputs are intentionally transmitted to the developer by the packaged skills.

Support: if you voluntarily open an issue in the public GitHub repository, the developer can see the GitHub username, issue title, text, attachments, and related public activity that you choose to submit. Do not include sensitive or confidential information in support issues.

Website: this is a static GitHub Pages website. It does not use developer-installed analytics, advertising trackers, custom cookies, or a contact form. GitHub may process connection information such as IP addresses and security logs to deliver and secure the site.

3. Why information is used

  • Plugin inputs are used in the host environment to generate the prompt (Lyra) or evidence-based workflow review (Iterloom) you requested.
  • Support issue information is used to investigate problems, answer questions, evaluate feature requests, and maintain the plugins.
  • Website connection information is handled by GitHub for hosting, security, and operations under GitHub's policies.

4. Recipients and disclosures

Relevant data may be processed by OpenAI or the host AI provider under your applicable account settings and that provider's privacy terms. If you elect to run a packaged helper or supply a file in the host environment, its execution and storage are controlled by that environment. The developer does not receive it merely because you use the plugin.

When you visit this website or create a support issue, GitHub processes website and issue data under its own terms. Public GitHub issues may be read by anyone. The developer does not sell personal data or disclose plugin inputs to advertisers.

5. Retention

  • Plugin inputs: no developer-operated retention period applies because the developer does not receive or store them. Retention inside ChatGPT, Codex, or another host is governed by that provider's policies and your account settings.
  • Support issues: content remains in the public GitHub repository until edited, removed, or otherwise handled in accordance with GitHub's retention practices.
  • Website logs: GitHub controls any security and service logs generated by GitHub Pages; the developer does not operate a separate visitor-log database.

6. Your choices and controls

  • Choose which messages, files, and exports to provide. Do not provide secrets or sensitive records unless appropriate for your host environment and task.
  • Use your AI host's account settings to manage conversation history, files, and data controls.
  • Edit or remove your own public GitHub issue content where GitHub permits; for removal assistance, use the support page.
  • Stop using or uninstall either plugin at any time.

7. Changes and contact

Material changes to plugin data handling will be reflected in an updated policy with a new effective date. For questions, contact the developer through the public support channel. Please do not post private records in an issue.
